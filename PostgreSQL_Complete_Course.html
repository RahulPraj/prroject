Phase 1 · Foundations

What is a Database?

A Database is simply a collection of organized data that can be easily accessed, managed, and updated.

The Simple Idea

Think of a database like a digital version of a well-organized notebook — where each page has information written in a structured way so you can search, update, and retrieve it easily.

In real life, companies like LinkedIn, Amazon, Flipkart, and Google store billions of records in databases. Every time you search for a product, like a post, or place an order — a database is doing the work behind the scenes.

In Technical Terms
💾

Stores Data Electronically

Data is stored on disk/servers — not in paper files or spreadsheets. Millions of records can be stored and retrieved in milliseconds.

📊

Organized in Tables

Just like an Excel sheet — rows and columns. Each row is a record. Each column is a field (name, age, price...).

🔍

Queryable with SQL

You use SQL (Structured Query Language) to read, insert, update, or delete data — in one clean line of code.

🔐

Consistency + Security

A database system ensures your data is always valid, consistent, and protected from unauthorized access or corruption.

Real Example — Students Table

Suppose you're building an app to store information about students. Instead of keeping a notebook, you store it in a database table:

This table is stored inside a database — and with SQL you can ask it:

-- Delete Raj's record
DELETE FROM students WHERE student_id = 3;

What is RDBMS?

RDBMS stands for Relational Database Management System. It's the software that lets you create, manage and query relational databases using SQL.

Breaking Down the Term
WordWhat it meansSimple Analogy
RelationalData is organized into tables that can be related to each otherLike linked Excel sheets
DatabaseA structured collection of data stored electronicallyA digital filing cabinet
Management SystemSoftware that lets you Create, Read, Update, Delete data using SQLThe librarian managing the filing cabinet
📖
An RDBMS is software that helps you store data in tables, relate them to each other, and perform operations on them using SQL.
Key Features of RDBMS
📋
Data Stored in Tables (Relations)
Each table has rows (records) and columns (fields) — just like an Excel sheet. Example: a Students table has columns like student_id, name, age, grade.
🔗
Relationships Between Tables
Tables can be connected to each other. Example: A Students table can be linked to a Courses table through an Enrollments table. This avoids repeating data everywhere.
🔤
Uses SQL (Structured Query Language)
You interact with an RDBMS using SQL commands: SELECT (read), INSERT (create), UPDATE (modify), DELETE (remove). SQL is the universal language of databases.
✅
ACID Compliant
Atomicity (all or nothing), Consistency (data is always valid), Isolation (transactions don't interfere), Durability (committed data is never lost). This makes RDBMS reliable for banking, e-commerce, etc.
Popular RDBMS Systems

🐬 MySQL
Very popular for web applications. Fast for simple queries. Used by WordPress, Facebook (early days).
📁 SQLite
Lightweight, file-based. Great for mobile apps and small projects. Used in Android, iOS apps.
🏢 Oracle Database
Enterprise-grade, very feature-rich, paid license. Used by large banks and government organizations.
🪟 SQL Server
Microsoft's RDBMS. Popular in Windows-based enterprise environments and .NET applications.
⭐
All these systems use SQL — so once you learn PostgreSQL, you can work with any of them!

Database · Schema · Table

PostgreSQL organizes data in a hierarchy. Understanding this structure is essential before writing any query.

The Full Hierarchy

Think of it like a company office building:

🐘 PostgreSQL Server — The engine that runs everything. Like the entire office building.
🗄️ Database — One floor of the building. e.g. LinkedIn_DB, Flipkart_DB. Multiple databases per server, each isolated.
📁 Schema — A room on the floor. e.g. public, analytics, admin. Default schema is always public.
📋 Table — A filing cabinet in the room. e.g. users, posts, orders. Rows = records. Columns = fields.
DATABASE in Detail

A database is an isolated container. You can have many databases inside one PostgreSQL server. Data in LinkedIn_DB is completely separate from Flipkart_DB. Different apps use different databases on the same server.

SQL
-- Create a new database
CREATE DATABASE LinkedIn_DB;

-- Connect to it in psql
\c LinkedIn_DB

-- See all databases
\l
SCHEMA in Detail

Inside a database, schemas act like namespaces or folders. They help organize tables, views, and functions. By default, every database has a public schema. Large apps create multiple schemas for separation of concerns.

LinkedIn_DB could have schemas:
public → users, posts, comments
analytics → page_views, click_events
admin → roles, permissions
billing → invoices, payments

Data Types in PostgreSQL

When you create a table, every column needs a data type — it tells PostgreSQL what kind of data that column will store. Choosing the right data type ensures data is stored efficiently and correctly.

Why Data Types Matter

If you store a phone number as INT, leading zeros get dropped. If you store a price as TEXT, you can't do math on it. Correct data types also save storage space and improve query performance.

🔢

Numeric Types

For whole numbers, decimals, auto-incrementing IDs.

🔤

Character Types

For names, descriptions, codes, emails — any text.

📅

Date & Time Types

For dates, times, timestamps, durations.

CRUD Operations

CRUD stands for Create, Read, Update, Delete — the four fundamental operations you perform on any database. Every application you've ever used does exactly these four things.

The CRUD Idea
➕

C — CREATE

INSERT INTO — Add new rows of data into a table.

👁️

R — READ

SELECT — Retrieve and view data from a table.

✏️

U — UPDATE

UPDATE SET — Modify existing data in a table.

🗑️

D — DELETE

DELETE FROM — Remove rows from a table.

Step 0 — Create the Table First

Before inserting data, we need to create the table with the correct structure and data types:

SQL — Create Table

  student_id  INT,
  name        VARCHAR(100),
  age         INT,
  grade       CHAR(1)

C — CREATE (INSERT INTO)

INSERT INTO adds new rows to a table. You specify the column names (optional but recommended) and then the VALUES.

SQL — INSERT Syntax & Examples
-- Syntax:
INSERT INTO table_name (col1, col2, col3)
VALUES (val1, val2, val3);

-- Insert one row:
INSERT INTO students (student_id, name, age, grade)
VALUES (1, 'Akarsh Vyas', 20, 'A');

-- Insert multiple rows at once (more efficient):
INSERT INTO students (student_id, name, age, grade)
VALUES
  (1, 'Akarsh Vyas',  20, 'A'),
  (2, 'Anjali Mehta', 21, 'B'),
  (3, 'Raj Gupta',    22, 'A');

R — READ (SELECT)

SELECT retrieves data. It's the most used SQL command. You can select all columns, specific columns, or filtered data.

SQL — SELECT in All Forms
-- 1. Select ALL columns, ALL rows (the * means everything)
SELECT * FROM students;
-- Returns all 3 rows with all 4 columns

-- 2. Select SPECIFIC columns only
SELECT name, grade
FROM students;
-- Returns only name and grade columns

-- 3. Select with WHERE condition (filter rows)
SELECT * FROM students
WHERE grade = 'A';
-- Returns: Akarsh(A) and Raj(A) — not Anjali(B)

-- 4. Select with multiple conditions
SELECT * FROM students
WHERE age > 20 AND grade = 'A';
-- Returns: Raj (age 22, grade A)
U — UPDATE (SET)

UPDATE modifies existing data. Use SET to specify which column and what new value. Always use WHERE to target specific rows!

SQL — UPDATE
-- Syntax:
UPDATE table_name
SET column = new_value
WHERE condition;

-- Update one column for one student:
UPDATE students
SET age = 22
WHERE name = 'Anjali Mehta';

-- Update multiple columns at once:
UPDATE students
SET age = 21, grade = 'A'
WHERE student_id = 2;
D — DELETE

DELETE FROM removes entire rows from a table. Always use WHERE — without it, ALL rows get deleted!

SQL — DELETE
-- Syntax:
DELETE FROM table_name
WHERE condition;

-- Delete Raj's record:
DELETE FROM students
WHERE student_id = 3;

-- ⚠️ DANGER — delete ALL rows!
DELETE FROM students;
-- Without WHERE: wipes the entire table!
⚠️
Golden Rule: Always use WHERE with UPDATE and DELETE. Without WHERE, you update or delete every single row in the table. This mistake has caused production disasters at major companies!

Phase 3 · Constraints

PRIMARY KEY Constraint

A Primary Key is a column (or combination of columns) that uniquely identifies each record in a table. Think of it like an Aadhaar Number — every person has one unique, never-null identity.

Why We Need a Primary Key

Suppose we have 100 employees. If two employees have the same name (Rahul Sharma), we need a unique way to tell them apart. That's where Employee_ID acts as the Primary Key — no two employees can ever have the same ID, and none can be missing an ID.

🚫
Cannot contain NULL values — every row MUST have an identity
🚫
Cannot contain DUPLICATE values — each row must be unique
1️⃣
Only ONE Primary Key constraint per table (though it can span multiple columns)
✅
Automatically enforces UNIQUE + NOT NULL — you don't need to add those separately
Syntax — 3 Ways to Define Primary Key
SQL — Primary Key Definition Methods
-- Method 1: Inline (most common)
CREATE TABLE Students (
  Student_ID    INT PRIMARY KEY,
  Student_Name  VARCHAR(50)
);

-- Method 2: Table-level constraint
CREATE TABLE Students (
  Student_ID    INT,
  Student_Name  VARCHAR(50),
  PRIMARY KEY (Student_ID)
);

-- Method 3: Auto-increment with SERIAL (recommended!)
CREATE TABLE Students (
  Student_ID    SERIAL PRIMARY KEY,  -- auto: 1,2,3,4...
  Student_Name  VARCHAR(50)
);
💡
Using SERIAL PRIMARY KEY is the best practice — you don't manually provide the ID. PostgreSQL auto-generates it as 1, 2, 3, 4... as you insert rows.
Full Example — Create, Insert, Query
SQL — Complete Primary Key Example
-- Create table with Primary Key

  Student_ID    INT PRIMARY KEY,

Important Points

✅ Valid — one Primary Key:

SQL
CREATE TABLE Students (
  Student_ID INT PRIMARY KEY
);

❌ Invalid — two Primary Keys:

SQL — ERROR
CREATE TABLE Students (
  Student_ID INT PRIMARY KEY,
  Roll_No    INT PRIMARY KEY  -- ❌!
);
🔑
Student_ID INT PRIMARY KEY is exactly equivalent to Student_ID INT NOT NULL UNIQUE. PRIMARY KEY combines both constraints automatically.

Note: A Composite Primary Key is allowed — one PK that spans two columns together. For example, in an enrollment table: PRIMARY KEY (student_id, course_id) — the combination must be unique, not individual columns alone.

Interview Questions
  • Q: What is a Primary Key?
    A column or combination of columns that uniquely identifies each row in a table. It enforces NOT NULL and UNIQUE automatically.
  • Q: Can a table have multiple Primary Keys?
    No. A table can have only ONE Primary Key constraint. However, a Primary Key can span multiple columns (Composite Primary Key).
  • Q: Can a Primary Key contain NULL values?
    No. Primary Key automatically includes the NOT NULL constraint.
  • Q: Can a Primary Key have duplicate values?
    No. Every Primary Key value must be unique across all rows.
  • Q: What's the difference between PRIMARY KEY and UNIQUE?
    PRIMARY KEY = UNIQUE + NOT NULL + only one per table. UNIQUE allows NULL, multiple per table.
Phase 3 · Constraints

FOREIGN KEY Constraint

A Foreign Key is a column in one table that references the PRIMARY KEY of another table. It creates a relationship between tables and enforces Referential Integrity.

The Core Concept — Referential Integrity

Without a Foreign Key, you could insert an employee into Department 10 — even if Department 10 doesn't exist! This creates "orphan records" — data that references nothing. Foreign Key prevents this.

👉
Simple rule: An employee can only belong to a department that ALREADY EXISTS in the Departments table. Foreign Key enforces this rule automatically.
Parent Table (Referenced)

Contains the PRIMARY KEY being referenced.
Example: Departments table with Department_ID as PK.

Child Table (Referencing)

Contains the FOREIGN KEY column.
Example: Employees table with Department_ID as FK.

Complete Step-by-Step Example
SQL — Step 1: Create Parent Table
-- Create the parent table first (it must exist before child)
CREATE TABLE Departments (
  Department_ID    INT PRIMARY KEY,
  Department_Name  VARCHAR(50)
);

INSERT INTO Departments VALUES
  (1, 'HR'),
  (2, 'IT'),
  (3, 'Finance');

CREATE TABLE Employees (
  Employee_ID    INT PRIMARY KEY,
  Employee_Name  VARCHAR(50),
  Department_ID  INT,

  -- Foreign Key: Department_ID here must exist in Departments table
  CONSTRAINT FK_Department
  FOREIGN KEY (Department_ID)
  REFERENCES Departments(Department_ID)

Interview Questions
  • Q: What is a Foreign Key? A column in one table that references the Primary Key of another table. It creates a relationship and maintains referential integrity.
  • Q: Why use Foreign Key? To maintain data consistency — prevents inserting a row that references a non-existent parent record.
  • Q: Can a Foreign Key have duplicate values? Yes! Many employees can reference the same department.
  • Q: Can a Foreign Key contain NULL? Yes, unless NOT NULL is also specified. NULL means "relationship not yet assigned."
  • Q: What happens if you try to delete a parent row that a child references? PostgreSQL throws an error — you can't delete HR if employees are assigned to HR. You'd need to reassign them first, or use ON DELETE CASCADE.
Phase 3 · Constraints

UNIQUE · NOT NULL · DEFAULT · CHECK

Four essential constraints that protect your data from bad, missing, or invalid inputs. Each solves a specific problem.

UNIQUE Constraint

Definition: The UNIQUE constraint ensures all values in a column are different. No two rows can have the same value in that column. Think of an employee's Email Address — every employee must have a different email.

When to use: Email, mobile number, Aadhaar number, PAN card, username — any field that must be unique per person but isn't the main identifier (that's PRIMARY KEY's job).

SQL — UNIQUE Examples
-- Method 1: Inline
CREATE TABLE Employees (
  Employee_ID  INT          PRIMARY KEY,
  Employee_Name VARCHAR(50),
  Email        VARCHAR(100) UNIQUE  -- no two same emails
);

-- ✅ Valid inserts:
INSERT INTO Employees VALUES (101, 'Rahul', 'rahul@gmail.com');
INSERT INTO Employees VALUES (102, 'Amit',  'amit@gmail.com');

-- ❌ Duplicate email → FAILS:
INSERT INTO Employees VALUES
  (103, 'Neha', 'rahul@gmail.com');
-- Error: duplicate key value violates unique constraint

-- ✅ NULL is allowed (NULL ≠ duplicate):
INSERT INTO Employees VALUES (104, 'Priya', NULL); -- works!

-- Composite UNIQUE (combination must be unique together):
CREATE TABLE Employees (
  Employee_ID  INT PRIMARY KEY,
  First_Name   VARCHAR(50),
  Last_Name    VARCHAR(50),
  UNIQUE (First_Name, Last_Name)  -- combo must be unique
);
-- Rahul Sharma (101) + Rahul Verma (102) = OK (different combo)
-- Adding another Rahul Sharma = FAIL (combo already exists)

NOT NULL Constraint

Definition: NOT NULL ensures a column CANNOT store NULL (empty/missing) values. If a column is NOT NULL, you MUST provide a value when inserting data. It's a mandatory field.

What is NULL? NULL means: no value / missing value / unknown value. It's not zero, not an empty string — it means the value simply doesn't exist.

SQL — NOT NULL Examples
-- Example 1: Single NOT NULL column
CREATE TABLE Employees (
  Employee_ID    INT         PRIMARY KEY,
  Employee_Name  VARCHAR(50) NOT NULL   -- mandatory!
);

-- ✅ Valid:
INSERT INTO Employees VALUES (101, 'Rahul'); -- works

-- ❌ NULL name → FAILS:
INSERT INTO Employees VALUES (102, NULL);
-- Error: null value in column "employee_name" violates not-null constraint

-- Example 2: Multiple NOT NULL columns
CREATE TABLE Employees (
  Employee_ID    INT           PRIMARY KEY,
  Employee_Name  VARCHAR(50)  NOT NULL,
  Salary         DECIMAL(10,2)NOT NULL,
  Joining_Date   DATE          NOT NULL
);

-- ✅ Valid:
INSERT INTO Employees VALUES
  (101, 'Rahul', 50000, '2025-01-15');

-- ❌ Salary is NULL → FAILS:
INSERT INTO Employees VALUES
  (102, 'Amit', NULL, '2025-02-01');
💡
Does NOT NULL prevent duplicates? NO! NOT NULL only prevents empty values. Two employees can both have salary = 50000. Use UNIQUE if you need to prevent duplicates.

Definition: DEFAULT assigns a predefined fallback value to a column when no value is provided during INSERT. Think of it as a pre-filled form field — if you leave it blank, the system fills it in for you.

Common use cases: Country = 'India' (most users are Indian), Status = 'Active' (new employees start active), Joining_Date = today, Stock = 0 (default out of stock).

CHECK Constraint

Definition: CHECK is like a security guard at the table entrance. It validates data against a custom condition. If the data satisfies the condition → ✅ Allowed. If not → ❌ Rejected. It enforces business rules directly in the database.

Common use cases: Age ≥ 18 (adult employee), Salary > 0 (no negative salary), Gender IN ('Male','Female') (valid options only), Rating BETWEEN 1 AND 5.

SQL — CHECK Examples

8. HAVING — Filter Groups (After GROUP BY)

HAVING filters groups after GROUP BY has run. It's like WHERE but for groups. You CANNOT use aggregate functions in WHERE — that's why HAVING exists.

SQL — HAVING vs WHERE

SELECT Department, COUNT(*) AS Total_Employees
FROM Employees
GROUP BY Department
HAVING COUNT(*) > 1;
-- Only IT (has 2 employees)

-- ❌ Wrong — can't use aggregate in WHERE:
SELECT Department, COUNT(*)
FROM Employees
GROUP BY Department
WHERE COUNT(*) > 1;  -- ❌ Error!

-- ✅ WHERE filters rows BEFORE grouping
-- HAVING filters groups AFTER grouping

Comparison Operators — =, !=, <, >, <=, >=
SQL — All Comparison Operators
-- = (Equal To): exact match
SELECT * FROM products
WHERE category = 'Electronics';
-- Returns: Laptop, Mobile (only exact match)

-- > (Greater Than): value above threshold
SELECT * FROM products
WHERE price > 5000;
-- Returns: Laptop(65000), Mobile(25000)

-- < (Less Than): value below threshold
SELECT * FROM products
WHERE price < 1000;
-- Returns: T-Shirt(800), Book(500)

-- >= (Greater Than or Equal To)
SELECT * FROM products
WHERE price >= 2000;
-- Returns: Laptop, Mobile, Shoes (Shoes=2000, 2000>=2000 is TRUE)

-- <= (Less Than or Equal To)
SELECT * FROM products
WHERE price <= 2000;
-- Returns: Shoes, T-Shirt, Book

-- != (Not Equal To) — also written as <>
SELECT * FROM products
WHERE category != 'Electronics';
-- Returns: Shoes, T-Shirt, Book (everything NOT Electronics)
Logical Operators — AND, OR, NOT

Logical operators combine or negate conditions. AND requires ALL conditions true. OR requires at least ONE condition true. NOT reverses the result.

SQL — AND, OR, NOT
-- AND: BOTH conditions must be TRUE
SELECT * FROM products
WHERE category = 'Electronics'
AND price > 30000;
-- Laptop: Electronics=TRUE AND 65000>30000=TRUE → ✅ returned
-- Mobile: Electronics=TRUE AND 25000>30000=FALSE → ❌ excluded

-- OR: at least ONE condition must be TRUE
SELECT * FROM products
WHERE category = 'Electronics'
OR category = 'Fashion';
-- Returns: Laptop, Mobile (Electronics), Shoes (Fashion)

-- NOT: reverses the condition
SELECT * FROM products
WHERE NOT is_available;
-- Returns: Book (is_available = FALSE → NOT FALSE = TRUE)

-- Combining AND + OR (use parentheses to control order!):
SELECT * FROM products
WHERE (category = 'Electronics' OR category = 'Fashion')
AND price > 1000;
-- Returns: Laptop, Mobile, Shoes (all > 1000 AND in those categories)
BETWEEN — Range Check (Inclusive)

BETWEEN checks if a value falls within a range. Both endpoints are included (≥ start AND ≤ end).

SQL
-- Products priced between 500 and 5000
SELECT * FROM products
WHERE price BETWEEN 500 AND 5000;
-- Returns: Shoes(2000), T-Shirt(800), Book(500)
-- 500 and 5000 are INCLUDED

-- Same as writing:
WHERE price >= 500 AND price <= 5000
IN — Multiple Values at Once

IN checks if a value matches any value in a list. Much cleaner than writing multiple OR conditions.

SQL
-- Products in Electronics or Fashion
SELECT * FROM products
WHERE category IN ('Electronics', 'Fashion');
-- Returns: Laptop, Mobile, Shoes

-- NOT IN: exclude those values
SELECT * FROM products
WHERE category NOT IN ('Electronics');
-- Returns: Shoes, T-Shirt, Book
LIKE — Pattern Matching with Wildcards

LIKE is used when you don't know the exact value — you search by pattern. It uses two special characters:

%
% (percent) = any number of characters (0 or more). Like a blank cheque for characters.
_
_ (underscore) = exactly ONE character. One specific slot.
SQL — LIKE Pattern Examples
-- Starts with 'L' (L + anything after)
SELECT * FROM products
WHERE name LIKE 'L%';
-- Returns: Laptop  (L + aptop)

-- Ends with 'e' (anything + e at end)
SELECT * FROM products
WHERE name LIKE '%e';
-- Returns: Mobile  (Mobil + e)

-- Contains 'op' anywhere
SELECT * FROM products
WHERE name LIKE '%op%';
-- Returns: Laptop  (L + op + top → contains 'op'? No wait: Lapt+op)

-- Exactly 1 char before 'ook' (underscore = exactly one char)
SELECT * FROM products
WHERE name LIKE '_ook';
-- Returns: Book  (B = 1 char, then ook)

-- Exactly 6 characters long (6 underscores)
SELECT * FROM products
WHERE name LIKE '______';
-- Returns: Laptop (6 chars), Mobile (6 chars)
IS NULL & IS NOT NULL

NULL means "no value / unknown." You cannot use = NULL — you MUST use IS NULL or IS NOT NULL.

SQL
-- Find rows where category is missing
SELECT * FROM products
WHERE category IS NULL;

-- Find rows that DO have a category
SELECT * FROM products
WHERE category IS NOT NULL;

-- ❌ Wrong — this doesn't work with NULL:
WHERE category = NULL  -- returns nothing!

Aggregate Functions

Aggregate functions perform calculations on multiple rows and return a single result. Instead of showing every row, they give you overall insights — total, average, highest, lowest, count.

Why Use Aggregate Functions?

Your manager asks: "How many products do we have? What's our average price? Which is the most expensive?" You could manually count or calculate — or let SQL do it instantly with aggregate functions.

🔢

COUNT()

How many rows match? Total count of records.

➕

SUM()

Total of all values in a numeric column.

📐

AVG()

Arithmetic average (mean) of all values.

🔽

MIN()

The smallest value in the column.

🔼

MAX()

The largest value in the column.

Products table: Laptop(₹65000, stock:10), Mobile(₹25000, stock:25), Shoes(₹2000, stock:50), T-Shirt(₹800, stock:100), Book(₹500, stock:0)
COUNT() — Count Rows

COUNT(*) counts ALL rows including NULLs. COUNT(column) counts only non-NULL values in that column.

SQL — COUNT
-- Total number of products
SELECT COUNT(*) AS Total_Products
FROM products;
-- Result: 5 (counts all 5 rows)

-- Count only available products (non-NULL / TRUE)
SELECT COUNT(is_available) AS Available_Count
FROM products
WHERE is_available = TRUE;
-- Result: 4 (Book is not available)

-- Count products per category
SELECT category, COUNT(*) AS num_products
FROM products
GROUP BY category;
SUM() — Add All Values
SQL
-- Total stock across all products
SELECT SUM(stock_quantity) AS Total_Stock
FROM products;
-- 10+25+50+100+0 = 185

-- Total stock per category
SELECT category,
       SUM(stock_quantity) AS Total_Stock
FROM products
GROUP BY category;

SQL
-- Average price of all products
SELECT AVG(price) AS Average_Price
FROM products;
-- (65000+25000+2000+800+500)/5
-- = 93300/5 = 18660

-- Average price per category
SELECT category,
       ROUND(AVG(price), 2) AS Avg_Price

FROM products;

-- Mobile | Electronics | 25000

5. SUBSTRING(), 8. LEFT(), 9. RIGHT() — Extract Part of String

These three functions let you extract a portion of a string — from the left, right, or middle.

SQL — Substring Extraction
-- SUBSTRING(text, start_position, length)
-- Start position counts from 1, not 0!
SELECT name, SUBSTRING(name, 1, 3)
FROM products;

-- Mobile → Mob  (M-O-B)
-- Shoes  → Sho

-- LEFT(text, n): first n characters from the left
SELECT LEFT(name, 3) FROM products;
-- Lap, Mob, Sho, T-S, Boo

-- RIGHT(text, n): last n characters from the right
SELECT RIGHT(name, 3) FROM products;
-- top (lapTOP), ile (mobILE), oes (shOES), irt (t-shIRT), ook (bOOK)

-- Practical: extract year from a date string
SELECT LEFT('2026-06-09', 4); -- 2026

REPLACE(text, old_value, new_value) — finds old_value in the text and replaces it with new_value. Case-sensitive.

-- Electronic Items (for Laptop, Mobile)

FROM products;

FROM products

ALTER TABLE

ALTER TABLE modifies the structure of an existing table — add columns, remove them, rename, change data types, add or drop constraints, or even rename the table itself. No need to drop and recreate!

Why ALTER TABLE?

Suppose you created a products table last month. Now your manager says: "We also need Brand, Stock category, and a GST column." You don't want to lose existing data by dropping and recreating the table — you just ALTER it. Think of it as editing an existing table without destroying it.

➕

Add Column

Add brand new column to existing table.

🗑️

Drop Column

Permanently remove a column and its data.

✏️

Rename Column

Give an existing column a new name.

🔄

Change Type

Switch a column's data type.

🔧

Set/Drop Default

Add or remove a default value.

🔒

Add/Drop Constraint

Add or remove CHECK, UNIQUE, FK constraints.

All 9 ALTER Operations — Syntax & Examples
SQL — All 9 ALTER TABLE Operations
-- 1. ADD COLUMN: add a brand new column
ALTER TABLE products
ADD COLUMN brand VARCHAR(50);
-- All existing rows get NULL in 'brand' column

-- 2. DROP COLUMN: permanently delete a column (and all its data!)
ALTER TABLE products
DROP COLUMN brand;
-- ⚠️ Data is gone! Cannot be undone.

-- 3. RENAME COLUMN: change a column's name
ALTER TABLE products
RENAME COLUMN name TO product_name;
-- Column 'name' is now called 'product_name'

-- 4. CHANGE DATA TYPE: alter a column's type
ALTER TABLE products
ALTER COLUMN category
TYPE VARCHAR(100);
-- Was VARCHAR(50), now can hold up to 100 chars

-- 5. SET DEFAULT: add a default value to existing column
ALTER TABLE products
ALTER COLUMN stock_quantity
SET DEFAULT 10;
-- Future inserts that skip stock_quantity get 10 automatically

-- 6. DROP DEFAULT: remove the default value
ALTER TABLE products
ALTER COLUMN stock_quantity
DROP DEFAULT;
-- No more auto-fill; column becomes NULL if not provided

-- 7. ADD CONSTRAINT: add a new rule to an existing column
ALTER TABLE products
ADD CONSTRAINT chk_price
CHECK (price > 0);
-- Now no product can have a price of 0 or negative

-- 8. DROP CONSTRAINT: remove a constraint
ALTER TABLE products
DROP CONSTRAINT chk_price;
-- Rule is removed; prices can be 0 again

-- 9. RENAME TABLE: give the entire table a new name
ALTER TABLE products
RENAME TO flipkart_products;
-- Table is now called 'flipkart_products'

CASE Statement

The CASE statement is a conditional expression in SQL — like an if-else in programming. It returns different values based on different conditions, all within a single query.

Why Use CASE?
  • Create a custom column on-the-fly without altering the table
  • Categorize data based on conditions (Expensive / Cheap)
  • Replace raw values with human-readable labels (TRUE → "In Stock")
  • Handle nulls gracefully (NULL → "Not Provided")
  • Simplify complex logic inside a single SELECT
  • Update multiple values conditionally in one UPDATE
Syntax
SQL — CASE Syntax
SELECT
  column_name,
  CASE
    WHEN condition1 THEN 'result1'
    WHEN condition2 THEN 'result2'
    WHEN condition3 THEN 'result3'
    ELSE 'default_result'    -- if none of the above match
  END AS custom_column_name
FROM table_name;

-- CASE checks conditions top-to-bottom
-- Returns the first matching THEN value
-- If nothing matches → returns ELSE
-- If no ELSE → returns NULL

    ELSE 'Cheap'
  END AS price_tag
FROM products;

Phase 6 · Relationships

SQL Relationships

In a relational database, data is stored across multiple connected tables. Instead of repeating data, we split it into tables and connect them with keys — avoiding redundancy and maintaining consistency.

Why Relationships?

Imagine storing a student's full address in every mark entry. If the student moves, you'd update hundreds of rows. Instead, store the address ONCE in a Students table, and link marks to that one record. That's the power of relationships.

📖
A relationship defines how many records in Table A can be associated with records in Table B. There are 3 types: One-to-One, One-to-Many, Many-to-Many.
1️⃣

One-to-One (1:1)

One record in Table A → exactly ONE in Table B.
Student ↔ Student Profile

🔥

One-to-Many (1:N)

One record in A → MANY in B. Most common!
Student → many Subject Marks

🌐

Many-to-Many (M:N)

Many in A ↔ Many in B. Needs junction table.
Students ↔ Courses

1. One-to-One (1:1) — Students & Profiles

Each student has exactly one profile. Each profile belongs to exactly one student. We enforce this by making student_id a PRIMARY KEY in both tables (PRIMARY KEY in child ensures at most one profile per student).

SQL — One-to-One (School DB)
-- Parent table
CREATE TABLE students (
  student_id  SERIAL PRIMARY KEY,
  name        VARCHAR(100) NOT NULL
);

-- Child table — student_id is BOTH PK and FK
-- PK ensures at most 1 profile per student → 1:1!
CREATE TABLE student_profiles (
  student_id  INT PRIMARY KEY,
  address     TEXT,
  age         INT,
  phone       VARCHAR(15)
);

-- Create the FK relationship
ALTER TABLE student_profiles
ADD CONSTRAINT fk_student_id
FOREIGN KEY (student_id)
REFERENCES students(student_id);

-- Insert data
INSERT INTO students (name)
VALUES ('Akarsh Vyas'), ('Simran Mehta'), ('Rohan Gupta');

INSERT INTO student_profiles (student_id, address, age, phone)
VALUES
  (1, 'Delhi, India',     22, '9999999999'),
  (2, 'Mumbai, India',    21, '8888888888'),
  (3, 'Bangalore, India', 23, '7777777777');

-- Query them together using JOIN
SELECT s.student_id, s.name,
       sp.address, sp.age, sp.phone
FROM students s
JOIN student_profiles sp
  ON s.student_id = sp.student_id;
2. One-to-Many (1:N) — Students & Marks

One student can have many subject marks. Each mark belongs to only one student. This is the MOST COMMON relationship in all databases.

SQL — One-to-Many (School DB)
CREATE TABLE students (
  student_id  SERIAL PRIMARY KEY,
  name        VARCHAR(100) NOT NULL
);

CREATE TABLE marks (
  mark_id     SERIAL PRIMARY KEY,
  student_id  INT,            -- FK to students
  subject     VARCHAR(50),
  marks       INT,
  FOREIGN KEY (student_id) REFERENCES students(student_id)
);

3. Many-to-Many (M:N) — Students & Courses

One student can enroll in many courses. One course can have many students enrolled. You CANNOT directly link M:N tables — you need a Junction Table (also called bridge/linking table) that breaks M:N into two 1:N relationships.

SQL — Many-to-Many with Junction Table
CREATE TABLE students (
  student_id   INT PRIMARY KEY,
  student_name VARCHAR(100)
);

CREATE TABLE courses (
  course_id   INT PRIMARY KEY,
  course_name VARCHAR(100)
);

-- Junction / Bridge table: breaks M:N into two 1:N
CREATE TABLE student_courses (
  student_id  INT,
  course_id   INT,
  PRIMARY KEY (student_id, course_id),   -- Composite PK
  FOREIGN KEY (student_id) REFERENCES students(student_id),
  FOREIGN KEY (course_id)  REFERENCES courses(course_id)
);

SQL JOINs

JOINs combine rows from two or more tables based on a related column. Think of JOINs as a bridge that lets you query multiple tables together in one SELECT statement.

Why JOINs?

Your data is split across multiple tables (students + marks). A JOIN brings it back together when you need to query across both. Without JOINs, you'd have to run separate queries and manually merge the results.

Join TypeWhat it returnsWhen to use
INNER JOINOnly matching rows from BOTH tablesWhen you only want records that have a match in both
LEFT JOINALL from left + matching from right (NULL if no match)Show all students even if they have no marks
RIGHT JOINALL from right + matching from left (NULL if no match)Show all marks even if student record is missing
FULL JOINEverything from BOTH tables (NULLs for unmatched)See all data with no exclusions
CROSS JOINEvery possible combination (Cartesian product)Generate all combinations (e.g. menu × size)

Returns rows where the ON condition matches in BOTH tables. Rows from either table with no match are excluded.

Phase 7 · Advanced

Views

A view is a virtual table based on a saved SQL query. It looks and behaves like a table when you query it, but it doesn't store data on its own — it runs the underlying query each time you access it.

Why Use Views?
🎯

Simplify Queries

Write a complex JOIN once, save it as a view, and use it like a simple table in future queries.

🔐

Security

Expose only selected columns to users. Hide salary, passwords, or sensitive columns from certain roles.

🔁

Reusability

No need to rewrite the same JOIN or filter logic in every query — define it once in the view.

View Syntax — Create, Use, Update, Drop
SQL — View Operations
-- CREATE VIEW: save a query with a name
CREATE VIEW view_name AS
SELECT column1, column2
FROM table_name
WHERE condition;

-- USE the view: query it like a normal table
SELECT * FROM view_name;

-- Add WHERE to a view query:
SELECT * FROM view_name
WHERE price > 1000;

-- UPDATE / REPLACE a view (redefine it)
CREATE OR REPLACE VIEW view_name AS
SELECT ...;

-- DROP VIEW: remove it
DROP VIEW view_name;
DROP VIEW IF EXISTS view_name; -- no error if not found
View 1 — Available Fitness Products
SQL
CREATE VIEW available_fitness_products AS
SELECT
  product_id,
  name,
  price,
  stock_quantity
FROM products
WHERE category = 'Fitness'
  AND is_available = TRUE;

-- Now use it like a table:
SELECT * FROM available_fitness_products;

-- Sort it:
SELECT * FROM available_fitness_products
ORDER BY price ASC;
View 2 — Low Stock Alert
SQL
CREATE VIEW low_stock_products AS
SELECT
  name,
  category,
  stock_quantity
FROM products
WHERE stock_quantity < 30;

-- Use it:
SELECT * FROM low_stock_products;
-- Shows: Laptop(10), Book(0)

-- View built on a JOIN:
CREATE VIEW student_marks_view AS
SELECT s.name, m.subject, m.marks

  ON s.student_id = m.student_id;
💡
Key point: A view doesn't store data. Every time you run SELECT * FROM view_name, PostgreSQL runs the underlying query fresh. This means the view always shows up-to-date data from the actual tables.
Phase 7 · Advanced

Stored Procedures

A stored procedure is a block of SQL code saved in the database with a name. Like a function in programming — define it once, call it whenever you need it. It can accept parameters and execute complex logic.

Why Stored Procedures?
🔁

Reusability

Write the logic once. Call it hundreds of times with different inputs. No copy-pasting queries.

🔐

Security

Users can CALL a procedure without needing direct table access. The logic stays in the DB.

⚡

Performance

Procedures are compiled and stored on the server — execute faster than sending raw queries each time.

📦

Encapsulation

Hide complex multi-step logic (insert + update + log) in one callable unit.

Syntax
SQL — Stored Procedure Structure
CREATE PROCEDURE procedure_name(
  param1 DATATYPE,
  param2 DATATYPE
)
LANGUAGE plpgsql
AS $$
BEGIN
  -- Your SQL logic here
  -- Can include INSERT, UPDATE, DELETE, IF/ELSE, loops...
END;
$$;

-- Call the procedure with values:
CALL procedure_name(value1, value2);
💡
plpgsql is PostgreSQL's procedural language. The $$ dollar-quoting marks the start and end of the procedure body. RAISE NOTICE is like print() — it outputs a message.
Example — Add Product Procedure
SQL — Create & Call Procedure
-- Define the procedure
CREATE PROCEDURE add_product(
  p_name      VARCHAR,
  p_sku       CHAR(8),
  p_price     NUMERIC,
  p_qty       INT,
  p_category  TEXT
)
LANGUAGE plpgsql
AS $$
BEGIN
  INSERT INTO products
    (name, sku_code, price, stock_quantity, category)
  VALUES
    (p_name, p_sku, p_price, p_qty, p_category);

  RAISE NOTICE 'Product added successfully!';
END;
$$;

-- Call it — add Headphones:
CALL add_product('Headphones', 'HEA10001', 3500, 15, 'Electronics');

-- Call it again — add Keyboard:
CALL add_product('Keyboard', 'KEY10001', 1200, 30, 'Electronics');

-- Instead of writing INSERT twice — one procedure, two calls!
