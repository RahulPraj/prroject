Imagine you run a shop and want to know which products sell the most, which days are busiest, and which customers keep coming back. Data analytics is exactly that — the science of collecting information, examining it, and turning it into useful knowledge that helps you make smarter decisions.

How Python actually runs your code
What happens when you press Run?
When you write Python code, the computer cannot understand it directly — computers only understand machine language (zeros and ones). Python acts as a translator between your human-readable instructions and machine code.
1. Your code (.py file)
— You write human-readable instructions
↓ Python reads it line by line
2. Bytecode (.pyc)
— Converted to a simplified middle format stored in __pycache__ folder
↓ PVM executes it
3. Python Virtual Machine (PVM)
— The actual engine that runs your program
↓
4. Output on your screen ✅
ℹ️
Because Python uses this step-by-step translation process, it is called an interpreted language. This also means if line 5 has an error, Python runs lines 1–4 successfully before stopping at the error — making it easy to debug.

Module 5 — Core Python
Conditional Statements
Conditionals let your program make choices. Just like in real life — "If it is raining, take an umbrella. Otherwise, wear sunglasses." Python uses if, elif (else-if), and else to make these decisions.
🔑
Key rule in Python: indentation (4 spaces or 1 tab) defines which code belongs to which block. Everything indented under an if belongs to that block. Unlike most languages, Python does NOT use curly braces { }.
🌿
if / elif / else — the full structure
Making multi-way decisions
conditionals.py
age = int(input("Enter your age: ")) if age < 13: # this block runs ONLY if age < 13 print("You are a child") elif age < 18: # runs if age is 13–17 (first condition was False) print("You are a teenager") elif age < 60: # runs if age is 18–59 print("You are an adult") else: # runs if NONE of the above conditions matched print("You are a senior citizen") print("Program finished") # always runs — not inside any block
💡
Python checks conditions from top to bottom and stops at the first True one. You can have as many elif blocks as you need, but only one if and one else.

Loops — Repeat Yourself
Imagine printing numbers 1 to 1000 manually — that would take forever! Loops let you run the same block of code many times automatically. Python has two types: the for loop (a set number of times) and the while loop (runs as long as a condition is true).
🔄
for loop with range()
Run code a specific number of times
range(start, stop, step) generates a sequence of numbers. The stop value is never included — so range(1, 6) gives 1, 2, 3, 4, 5.
for_loops.py
# Print numbers 1 to 5 for i in range(1, 6): # stop=6 so last number is 5 print(i) # 1, 2, 3, 4, 5 # Count even numbers using step=2 for i in range(0, 11, 2): print(i) # 0, 2, 4, 6, 8, 10 # Count backwards from 10 to 1 for i in range(10, 0, -1): # step=-1 means going down print(i) # 10, 9, 8 ... 1 # Loop through a string character by character name = "Python" for letter in name: print(letter) # P y t h o n # Multiplication table of any number n = int(input("Which table? ")) for i in range(1, 11): print(f"{n} x {i} = {n * i}") # Sum of first n numbers n = 10 total = 0 for i in range(1, n + 1): total += i # total = total + i print(f"Sum 1 to {n} = {total}") # Sum 1 to 10 = 55 # Factorial of a number n = int(input("Enter number: ")) fact = 1 for i in range(1, n + 1): fact *= i print(f"Factorial of {n} = {fact}")
⏳
while loop — condition-based repetition
Runs as long as the condition stays True
Use a while loop when you do not know in advance how many times to loop. The loop keeps running as long as the condition is True. If the condition never becomes False, it runs forever — this is called an infinite loop and will freeze your program.
while_loops.py
# Basic while loop count = 1 while count <= 5: print(count) count = count + 1 # MUST change count or it loops forever! # Reverse digits of a number a = int(input("Enter number: ")) rev = 0 while a > 0: rev = rev * 10 + a % 10 # extract last digit a = a // 10 # remove last digit print("Reversed:", rev) # Number guessing game — while True with break import random secret = random.randint(1, 10) tries = 0 while True: guess = int(input("Guess a number 1-10: ")) tries += 1 if guess == secret: print(f"Correct! You took {tries} tries") break # exit loop immediately elif guess < secret: print("Too low! Go higher.") else: print("Too high! Go lower.")

Functions — Reusable Code
Imagine writing the same 10 lines of code every time you want to do the same task. Functions solve this — write the code once, give it a name, and call that name whenever you need it. This is one of the most important concepts in all of programming.
🍕 Real-World Analogy
A function is like a recipe. You write it once ("mix flour, add water, bake at 200°C for 30 minutes"). Every time you want bread, you just say "make_bread()" instead of rewriting all the steps. Functions let you build programs like LEGO — snap reusable pieces together.
📋

Lists — everything you need to know
Creating, accessing, modifying, looping
lists.py
# Creating lists — square brackets, comma-separated fruits = ["apple", "banana", "cherry", "mango"] numbers = [10, 20, 30, 40, 50] mixed = ["Rahul", 24, True, 3.14] # lists can mix data types! # Accessing items — same indexing rules as strings print(fruits[0]) # apple — first item (index starts at 0) print(fruits[-1]) # mango — last item print(fruits[1:3]) # ['banana', 'cherry'] — slicing # Modifying — lists are mutable, values can be changed fruits[0] = "watermelon" # replace apple with watermelon # Adding items fruits.append("grape") # add to the END of the list fruits.insert(1, "kiwi") # insert at position 1 # Removing items fruits.remove("banana") # remove by VALUE popped = fruits.pop(2) # remove by INDEX, returns the removed item # Sorting and reversing numbers.sort() # sort ascending [10,20,30,40,50] numbers.sort(reverse=True) # sort descending [50,40,30,20,10] numbers.reverse() # flip current order # Useful functions print(len(fruits)) # number of items in list print("mango" in fruits) # True — check if item exists print(fruits.count("apple")) # how many times apple appears print(fruits.index("cherry")) # at which index is cherry? copy = fruits.copy() # create an independent copy fruits.clear() # empty the entire list # Looping — two common ways scores = [85, 92, 78, 95, 88] # Way 1: directly loop over values for score in scores: print(score) # Way 2: loop using index (when you need the position) for i in range(len(scores)): print(f"Index {i}: {scores[i]}") # Practice: find the largest number nums = [12, 34, 56, 17, 120, 55, 100] largest = nums[0] index = 0 for i in range(len(nums)): if nums[i] > largest: largest = nums[i] index = i print(f"Largest: {largest} at index {index}") # Largest: 120 at index 4
⚠️
Never do b = a to copy a list — this makes b point to the SAME list, so changes in b also change a! Always use b = a.copy() to create a separate independent copy.

Tuples — immutable sequences
When your data must never change
Use tuples for data that must stay fixed — GPS coordinates, RGB colours, database records, days of the week. They are faster than lists and protect important data from accidental change.

Dictionary & Set
A dictionary stores data as key-value pairs — like a real dictionary where you look up a word (key) and get its meaning (value). A set stores only unique values — no duplicates allowed, ever.
📖
Dictionary — key-value storage
The most powerful built-in data structure
In a list you access items by position (0, 1, 2...). In a dictionary you access them by a meaningful key like "name", "age", "city". This makes your code much more readable and organised.
dictionaries.py
# Creating — curly braces, key: value pairs student = { "name" : "Rahul", "age" : 24, "city" : "Mumbai", "marks" : [85, 92, 78] # values can be any type, even lists! } # READ — access by key name print(student["name"]) # Rahul print(student["marks"][0]) # 85 (first mark) print(student.get("salary", 0)) # 0 (safe — no crash if key missing) # UPDATE — change an existing value student["age"] = 25 student.update({"city": "Delhi", "age": 26}) # update multiple at once # CREATE — add a new key-value pair student["email"] = "rahul@email.com" # DELETE — remove a key-value pair del student["city"] # removes key and its value val = student.pop("email") # removes and returns the value # Check if a key exists print("name" in student) # True print("salary" in student) # False # Traverse all key-value pairs for key, value in student.items(): print(f"{key}: {value}") # Real use case: count frequency of elements marks = [85, 92, 85, 78, 92, 85, 100] frequency = {} for mark in marks: if mark in frequency: frequency[mark] += 1 else: frequency[mark] = 1 print(frequency) # {85: 3, 92: 2, 78: 1, 100: 1}
⭕
Set — unique values and powerful operations
No duplicates · Unordered · Fast lookup
Sets automatically remove duplicate values. They also support powerful mathematical operations like union, intersection, and difference — like Venn diagrams in school maths.
sets.py
# Creating a set — curly braces but NO key:value pairs colours = {"red", "blue", "green", "blue", "red"} print(colours) # {'red', 'blue', 'green'} — duplicates auto-removed! # Common use case: remove duplicates from a list names = ["Alice", "Bob", "Alice", "Charlie", "Bob"] unique = list(set(names)) print(unique) # ['Alice', 'Bob', 'Charlie'] # Set operations — like Venn diagrams in mathematics class_A = {"Alice", "Bob", "Charlie", "David"} class_B = {"Charlie", "David", "Eve", "Frank"} # Union — all students from EITHER class print(class_A | class_B) # {'Alice','Bob','Charlie','David','Eve','Frank'} # Intersection — students in BOTH classes print(class_A & class_B) # {'Charlie', 'David'} # Difference — only in class_A, NOT in class_B print(class_A - class_B) # {'Alice', 'Bob'} # Symmetric difference — in one but NOT both print(class_A ^ class_B) # {'Alice','Bob','Eve','Frank'} # Adding and removing from a set s = {1, 2, 3} s.add(4) # adds element s.remove(2) # removes element (crashes if not found) s.discard(99) # removes element (NO crash if not found)
Module 10 — Advanced
Object Oriented Programming
OOP is a way of organising large programs by modelling them around real-world objects. Instead of writing thousands of scattered lines of code, you group related data and functions together into neat structures called classes.
🏗️ The Blueprint Analogy
A class is like an architectural blueprint for a house. The blueprint describes what every house will have — bedrooms, kitchen, a front door. An object is an actual house built from that blueprint. You can build 100 different houses from the same blueprint — each house is a separate object with its own address, colour, and furniture.
🏛️
Class, Object & Constructor
The three building blocks of OOP
Class = the blueprint. Object = an instance built from the blueprint. Constructor (__init__) = a special method that runs automatically the moment an object is created, setting up its initial data.
classes.py
class Student: # __init__ = constructor — runs automatically when object is created # 'self' refers to the specific object being created def __init__(self, name, age, grade): self.name = name # instance attributes (each object has its own) self.age = age self.grade = grade def introduce(self): # instance method — action the object can perform print(f"Hi! I'm {self.name}, age {self.age}, grade {self.grade}") def study(self, subject): print(f"{self.name} is studying {subject}") # Creating OBJECTS (instances) from the class s1 = Student("Rahul", 20, "A") # constructor called automatically s2 = Student("Priya", 21, "B") s3 = Student("Amit", 22, "A+") # Each object has its OWN copy of attributes print(s1.name) # Rahul print(s2.grade) # B print(s3.age) # 22 # Call methods on objects s1.introduce() # Hi! I'm Rahul, age 20, grade A s2.study("Python") # Priya is studying Python
The 4 Pillars of OOP
🧬
1. Inheritance
A child class inherits all attributes and methods from a parent class. Avoids rewriting duplicate code. Example: a Dog class can inherit from Animal and get eat(), breathe() methods for free.
🎭
2. Polymorphism
Same method name behaves differently based on which class calls it. A speak() method returns "Woof" for Dog and "Meow" for Cat — same name, completely different behaviour.
🔒
3. Encapsulation
Bundle data and methods together and control who can access them. Use _ (protected) or __ (private) prefixes. Prevents accidental modification of sensitive data.
🎨
4. Abstraction
Show only what is necessary, hide complexity. Like a TV remote — you press On/Off without knowing the circuit board inside. Achieved in Python using the ABC module.
🧬
Inheritance — parent and child classes
Reuse code across related classes
inheritance.py
class Animal: # PARENT class def __init__(self, name, age): self.name = name self.age = age def breathe(self): print(f"{self.name} breathes air") def eat(self): print(f"{self.name} is eating") class Dog(Animal): # CHILD class — inherits from Animal def __init__(self, name, age, breed): super().__init__(name, age) # call parent constructor self.breed = breed # Dog's own extra attribute def speak(self): # Dog's own method print(f"{self.name} says: Woof! Woof!") class Cat(Animal): # another child class def speak(self): print(f"{self.name} says: Meow!") dog = Dog("Buddy", 3, "Labrador") cat = Cat("Whiskers", 2) dog.breathe() # Buddy breathes air — inherited from Animal dog.eat() # Buddy is eating — inherited from Animal dog.speak() # Buddy says: Woof! — Dog's own method cat.speak() # Whiskers says: Meow! — Cat's own method (polymorphism) print(dog.breed) # Labrador — Dog's own attribute
💡
super() calls the parent class constructor. It is how you pass values up to the parent so you do not have to re-write the same assignment code. Always use it in child constructors.
Module 11 — Advanced
Exception Handling
Things go wrong in programs. Users type letters where numbers are expected. Files are missing. Networks fail. Exception handling lets you manage these errors gracefully instead of crashing with an ugly error message.
🚗 Real-World Analogy
Exception handling is like a car's airbag system. The car (your program) runs normally. When a crash happens (an error), instead of being completely destroyed, the airbag (your except block) deploys and handles the situation. The finally block is like post-accident cleanup — it always runs whether there was a crash or not.
KeywordPurposeWhen does it run?
tryWrap code that might cause an errorAlways — this is where the risky code goes
exceptHandle the error if it occursOnly if an error occurred inside the try block
elseCode to run on successOnly if NO error occurred in try block
finallyCleanup codeALWAYS — whether or not an error occurred
raiseManually throw your own errorWhen you want to enforce your own conditions
🛡️
Complete exception handling example
try / except / else / finally
exceptions.py
a = int(input("Enter a number: ")) try: result = 100 / a # this crashes if a = 0 print(f"Result: {result}") except ZeroDivisionError: # catches ONLY division by zero print("You cannot divide by zero!") except ValueError: # catches if input was not a number print("Please enter a valid number") except Exception as err: # catches ANY other unexpected error print(f"Something went wrong: {err}") else: print("Division was successful!") # only if no error occurred finally: print("Program completed.") # ALWAYS prints, no matter what

raise_example.py
def set_age(age): if age < 0 or age > 150: raise ValueError(f"Age {age} is not realistic") print(f"Age set to {age}") def withdraw(balance, amount): if amount > balance: raise ValueError("Insufficient funds!") return balance - amount try: set_age(-5) except ValueError as e: print(f"Error: {e}") # Error: Age -5 is not realistic try: new_balance = withdraw(500, 1000) except ValueError as e: print(f"Transaction failed: {e}") # Insufficient funds!

Decorators — wrapping functions
Add behaviour to functions without modifying them
A decorator is a function that takes another function as input, wraps it with extra behaviour before or after, and returns the improved version. Used heavily in web frameworks (Flask, Django) for authentication, logging, and caching.
decorators.py
# A decorator is simply a function that wraps another function def timer_decorator(func): def wrapper(*args, **kwargs): print(f"Starting: {func.__name__}") result = func(*args, **kwargs) # call the original function print(f"Finished: {func.__name__}") return result return wrapper # Apply the decorator with @ syntax — runs timer_decorator(calculate_sum) @timer_decorator def calculate_sum(n): total = sum(range(n + 1)) print(f"Sum of 1 to {n} = {total}") return total calculate_sum(100)
Output
Starting: calculate_sum Sum of 1 to 100 = 5050 Finished: calculate_sum

*args and **kwargs — flexible function inputs
Accept any number of arguments
*args collects any number of positional arguments into a tuple. **kwargs collects keyword arguments into a dictionary. The * and ** are what matter — the names args and kwargs are just convention.
args_kwargs.py
# *args — accept any number of positional arguments as a tuple def add_all(*numbers): print(f"Received: {numbers}") # it's a tuple! return sum(numbers) print(add_all(1, 2, 3)) # 6 print(add_all(10, 20, 30, 40, 50)) # 150 print(add_all(5)) # 5 — works with any count # **kwargs — accept any number of keyword arguments as a dictionary def create_profile(**details): print("User Profile:") for key, value in details.items(): print(f" {key.capitalize()}: {value}") create_profile(name="Rahul", age=24, city="Mumbai", role="student") # User Profile: # Name: Rahul # Age: 24 # City: Mumbai # Role: student
